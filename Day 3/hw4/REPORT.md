## 1. 개요 (Overview)
본 과제는 ATmega128의 USART 하드웨어를 사용하지 않고, PORTD와 DDRD만으로 UART 송신 파형을 직접 생성하는 것을 목표로 함. 하드웨어가 자동으로 처리하던 프레임 구성과 비트 타이밍을 소프트웨어로 재현하며, 이를 통해 UART 통신의 물리 계층 동작을 확인함.

### 핵심 목표
* UART 프레임 구조(Start, Data, Stop)의 직접 구현
* 9600bps에 해당하는 비트 폭의 정밀한 생성
* 타이밍 오차 요인 분석 및 허용 범위 확인
* "HelloWorld!" 문자열의 1초 주기 전송

## 3. 하드웨어 구성 및 핀 맵 (Hardware Structure)

### Pin Configuration

```text
[ATmega128]                 [Target Component]
 PD3                 ----->   USB-Serial 어댑터 RX
 GND                 <---->   어댑터 GND
 PA0                 ----->   LED (전송 표시용)
```

### 송신 핀 선택
PD3는 하드웨어 UART1의 TXD1에 해당하는 핀이나, 본 과제에서는 USART 기능을 활성화하지 않고 범용 출력으로만 사용함. 과제 3에서 PC 연결 케이블이 이미 UART1 헤더에 결선되어 있어, 배선 변경 없이 그대로 사용할 수 있다는 점에서 선택함.

과제 3에서 문제가 되었던 PD2의 104 커패시터는 수신 경로에만 영향을 주며, 본 과제는 송신만 수행하므로 무관함. 따라서 보레이트를 낮출 필요 없이 요구 사양인 9600bps를 그대로 사용함.

## 5. 핵심 코드 및 레지스터 설정 (Key Implementation)

### UART 프레임 구조
UART는 유휴 상태에서 High를 유지하며, 한 바이트를 아래 순서로 전송함.

```text
      ____        ___ ___         ___________
idle      |______|   |   |_______|           idle
          Start   D0  D1  D2 ...  Stop
          (0)     LSB 부터        (1)
```

| 구간 | 값 | 길이 |
| :--- | :--- | :--- |
| Start bit | 항상 0 | 1비트 |
| Data bits | LSB부터 8비트 | 8비트 |
| Stop bit | 항상 1 | 1비트 |

9600bps이므로 1비트의 길이는 `1 / 9600 = 104.17us`임. 결국 구현해야 할 동작은 핀을 정해진 순서대로 High, Low로 설정하고 각 구간마다 104us씩 유지하는 것임.

### 송신 함수 (hw4.c)
```c
void SEND_softByte(uint8_t byte)
{
    uint8_t sreg = SREG;

    cli();                                  // 프레임 중 인터럽트가 끼면 비트 폭이 틀어진다

    PORTD &= ~(1 << TX_PIN);                // Start bit
    _delay_us(BIT_US);

    for (i = 0; i < 8; i++)
    {
        if (byte & 0x01)
            PORTD |= (1 << TX_PIN);
        else
            PORTD &= ~(1 << TX_PIN);

        byte >>= 1;
        _delay_us(BIT_US);
    }

    PORTD |= (1 << TX_PIN);                 // Stop bit
    _delay_us(BIT_US);

    SREG = sreg;                            // 인터럽트 상태 복구
}
```

데이터는 LSB부터 전송해야 하므로 최하위 비트를 검사한 뒤 오른쪽으로 시프트하는 방식을 반복함.

프레임 전송 도중 인터럽트가 발생하면 해당 비트의 폭이 인터럽트 처리 시간만큼 늘어나 수신 측의 샘플링 위치가 어긋남. 본 프로그램은 인터럽트를 사용하지 않으나, 이후 확장 시의 오동작을 막기 위해 프레임 단위로 인터럽트를 차단함. SREG를 저장했다가 복원하는 방식을 사용하여 호출 전의 인터럽트 상태를 보존함.

### 타이밍 오차 분석

| 항목 | 값 |
| :--- | :--- |
| 이상적인 1비트 | 16MHz / 9600 = 1666.67 사이클 |
| `_delay_us(104)` | 1664 사이클 |
| 핀 조작 및 루프 오버헤드 | 약 7 사이클 |
| 실제 1비트 | 약 1671 사이클 |
| 오차 | 약 +0.3% |

UART의 허용 오차는 일반적으로 ±2~3% 수준이므로 충분한 여유가 있음. PORTD는 SBI, CBI 명령이 적용되는 I/O 주소 범위에 있어 비트 조작이 2사이클로 처리되며, 이것이 오버헤드를 작게 유지하는 요인임.

`-Os` 최적화가 필수인 이유도 여기에 있음. 최적화를 끄면 루프와 비트 조작에 소요되는 명령 수가 늘어나 오버헤드가 커지고, 비트 폭이 설계값을 벗어남.

### 초기화 순서
```c
void INIT_softTx(void)
{
    PORTD |= (1 << TX_PIN);                 // 순서 주의. DDRD 를 먼저 바꾸면
    DDRD |= (1 << TX_PIN);                  // 핀이 잠깐 Low -> 앞에 쓰레기 문자

    _delay_ms(1);
}
```
DDRD를 먼저 출력으로 설정하면 그 시점의 PORTD 해당 비트가 아직 0이므로 핀이 순간적으로 Low로 떨어짐. 수신 측은 이 Low를 Start bit로 인식하여 의미 없는 문자를 1개 수신함. PORTD를 먼저 1로 설정한 뒤 방향을 전환하면 출력 전환 즉시 High가 출력되어 이 현상이 발생하지 않음.

## 6. 동작 설명 및 결과 (Results)

### 동작 시나리오
1. 전원 인가 시 PD3을 High 상태의 출력으로 설정함
2. 1ms 대기하여 수신 측이 유휴 상태를 인식하도록 함
3. "HelloWorld!\r\n"을 한 글자씩 프레임으로 변환하여 전송함
4. 전송할 때마다 PA0을 반전시켜 동작을 표시함
5. 1초 대기 후 반복함

```text
HelloWorld!
HelloWorld!
HelloWorld!
```

### 검증 과정에서 확인한 사항

**초기 쓰레기 문자**
구현 초기 버전에서 첫 전송 앞에 의미 없는 문자가 1개 붙어 출력됨. 파형을 확인한 결과 초기화 시점에 PD3이 짧게 Low로 떨어지는 구간이 존재했으며, 이것이 Start bit로 해석된 것임. DDRD와 PORTD의 설정 순서를 바꾸어 해결함.

**비트 폭 실측**
전송 파형의 프레임 간격을 측정한 결과 10비트에 해당하는 구간이 16738 사이클로 나타남. 이상값 16666.67 사이클 대비 오차는 -0.43%이며, 실효 보레이트는 9559bps로 환산됨. UART 허용 오차 범위 내이므로 별도 보정 없이 사용함.

| 항목 | 이상값 | 실측값 |
| :--- | :--- | :--- |
| 10비트 구간 | 16666.67 사이클 | 16738 사이클 |
| 보레이트 | 9600 bps | 9559 bps |
| 오차 | 0% | -0.43% |

Stop bit는 모든 프레임에서 정상적으로 High가 유지됨을 확인함.
