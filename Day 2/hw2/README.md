## 1. 개요 (Overview)
본 과제는 ATmega128의 내장 10비트 ADC로 가변저항의 전압을 측정하고, 그 결과를 LED와 I2C 텍스트 LCD에 동시에 출력하는 것을 목표로 함. 아날로그 입력의 디지털 변환 과정과 I2C 통신 기반 주변장치 제어를 함께 다룸.

### 핵심 목표
* ADMUX / ADCSRA 설정을 통한 ADC 초기화 및 단극성 변환
* 데이터시트 권장 범위(50 부터 200kHz)에 맞춘 ADC 클럭 분주비 선정
* 실수 연산 없이 정수만으로 전압값 환산 및 표시
* TWI(I2C) 하드웨어를 이용한 PCF8574 기반 텍스트 LCD 제어

## 3. 하드웨어 구성 및 핀 맵 (Hardware Structure)

### Pin Configuration

```text
[ATmega128]                 [Target Component]
 PORTA (PA0 ~ PA7)   ----->   8-Bit LED (Active Low)
 ADC0 (PF0)          <-----   가변저항 (Potentiometer, 분압 출력)
 PD0 (SCL)           <---->   I2C Text LCD 16x2
 PD1 (SDA)           <---->   I2C Text LCD 16x2
 AVCC / AREF         <-----   5V (ADC 전용 전원 및 기준전압)
```

### 주요 회로 특징
* **가변저항:** 5V와 GND 사이에 연결되고 가운데 단자(SIGNAL)가 PF0으로 입력됨. 3핀 커넥터로 연결되며 방향이 바뀌면 PF0이 전원 레일에 직결됨
* **ADC 전원:** ATmega128은 ADC 전용 전원 핀 AVCC를 별도로 가짐. VCC와의 차이가 0.3V 이내여야 하며 미연결 시 변환 결과가 비정상적으로 고정됨
* **LCD:** 07/29 수정 회로도에서 병렬 4비트에서 I2C 모듈로 변경됨. PD0이 SCL, PD1이 SDA에 해당하며 이는 ATmega128의 TWI 하드웨어 핀과 일치함
* **주의사항:** 배포된 LCD_Text.c 는 병렬 방식으로 DDRC 전체를 출력으로 설정함. 수정 회로도에서 PC0, PC1에는 스위치가 연결되어 있으므로 해당 핀이 출력 상태에서 스위치가 눌리면 GND로 직결되어 핀 손상 위험이 있음. 따라서 본 과제에서는 사용하지 않음

## 5. 핵심 코드 및 레지스터 설정 (Key Implementation)

### ADC 초기화 (hw2.c)
```c
DDRF  &= ~(1 << PF0);                // ADC0 입력 설정
PORTF &= ~(1 << PF0);                // ADC 핀은 내부 풀업을 꺼야 함

ADMUX  = (1 << REFS0);               // REFS1:0 = 01 이면 AVCC 기준, MUX = 0 이면 ADC0
ADCSRA = (1 << ADEN)                 // ADC 전원 ON
       | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);   // 분주비 128
```
데이터시트 233쪽에 따르면 축차비교 회로는 50 부터 200kHz 범위에서만 10비트 정확도가 보장됨. 16MHz를 128로 분주하면 125kHz가 되어 범위 내에 들어감.

### 변환 수행
```c
uint16_t adcRead(void)
{
    ADCSRA |= (1 << ADSC);           // 변환 시작
    while (ADCSRA & (1 << ADSC));    // 완료 시 하드웨어가 ADSC를 0으로 내림
    return ADC;                      // ADCL, ADCH 결합 (0 부터 1023)
}
```
데이터시트상 ADCL을 먼저 읽고 ADCH를 읽어야 하나, avr-libc가 제공하는 ADC 매크로는 16비트 접근으로 이 순서를 보장함.

### 전압 환산 (정수 연산)
```c
mv = (uint32_t)adc * 5000 / 1023;                        // 0 부터 5000 mV
sprintf(buf, "%d.%02dV", mv / 1000, (mv % 1000) / 10);
```
avr-libc의 sprintf 는 기본 설정에서 실수 형식 지정자를 지원하지 않으며, 링크 옵션으로 활성화할 경우 코드 크기가 크게 증가함. mV 단위 정수로 계산한 뒤 몫과 나머지로 소수점을 구성함. 1023 곱하기 5000 은 5,115,000 으로 16비트를 초과하므로 uint32_t 캐스팅이 필요함.

### LED 위치 산출
```c
pos = adc >> 7;                      // 0 부터 1023 을 8단계로 분할
PORTA = ~(1 << pos);
```
1023을 7비트 우측 시프트하면 7이 되어 0 부터 7 범위에 정확히 대응함.

## 6. 동작 설명 및 결과 (Results)

### 동작 시나리오
1. 전원 인가 시 PORTA 출력 설정, ADC 초기화, I2C LCD 초기화를 순차 수행함
2. LCD 1행에 ADC 라벨과 이니셜, 2행에 VOL 라벨을 고정 문자열로 출력함
3. 0.1초 주기로 ADC0 채널을 변환함
4. 변환값 상위 3비트로 LED 위치를 결정하여 1개만 점등함
5. 변환값을 4자리로 LCD 1행에 표시함
6. 변환값을 mV로 환산하여 소수점 둘째 자리까지 LCD 2행에 표시함

```text
+----------------+
|ADC: 512     LDY|
|VOL:2.50V       |
+----------------+
```

### 검증 과정에서 확인한 사항
초기 업로드 시 ADC와 LCD가 동시에 동작하지 않음. 원인은 LCD 미응답 시 TWI 완료 대기 루프가 무한 대기에 진입하여 초기화 단계에서 프로그램이 정지한 것임. 메인 루프에 도달하지 못해 ADC까지 정지한 것처럼 관측됨. 대기 루프에 타임아웃을 추가하여 두 문제를 분리한 뒤 개별 진단이 가능해짐.

ADC 측은 변환값이 1023에 고정되는 증상이었음. 레지스터 설정을 데이터시트와 재확인하고 기준전압까지 점검하였으나, 실제 원인은 가변저항 커넥터의 연결 오류로 PF0이 5V에 직결된 것이었음. 재연결 후 정상 동작함.

LCD는 I2C 주소 0x27로 응답하고 백라이트도 점등되나 문자가 표시되지 않았음. 백팩의 핀 배치 변종을 의심하여 두 가지 배치를 교대 적용하는 테스트를 수행하였으나, 실제 원인은 대비(contrast) 조절이었음. 화면 전체를 블록 문자로 채운 상태에서 백팩의 트리머를 조절하여 확인함. 보드에 실장된 가변저항과 LCD 대비용 트리머를 혼동한 것이 원인 파악을 지연시킴.
