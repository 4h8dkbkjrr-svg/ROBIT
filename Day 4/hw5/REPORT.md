## 1. 개요 (Overview)
본 과제는 Timer1의 Fast PWM 기능으로 서보모터 제어 신호를 생성하고, UART로 입력받은 각도에 따라 서보를 이동시키는 것을 목표로 함. 서보 제어에 요구되는 주기와 펄스 폭을 타이머 설정으로 정확히 구현하고, 문자열 형태의 입력을 정수로 변환하여 검증하는 과정을 다룸.

### 핵심 목표
* Timer1 Fast PWM을 이용한 20ms 주기 신호 생성
* 각도를 펄스 폭으로 변환하는 매핑 구현
* UART 문자열 입력의 정수 변환 및 유효성 검사
* 전원 투입 시 지정된 원점으로의 안전한 복귀

## 3. 하드웨어 구성 및 핀 맵 (Hardware Structure)

### Pin Configuration

```text
[ATmega128]                 [Target Component]
 PB7 (OC1C)          ----->   서보 SIGNAL (노란색)
 PD2 (RXD1)          <-----   USB-Serial 어댑터 TX
 PD3 (TXD1)          ----->   USB-Serial 어댑터 RX
 GND                 <---->   서보 GND, 어댑터 GND

[서보 3핀 커넥터]
 1 : GND (갈색)      <---->   보드 GND
 2 : 5V  (적색)      <-----   레귤레이터 5V
 3 : SIGNAL (노란색) <-----   PB7
```

### 서보 전원 분리
서보 전원은 반드시 보드와 별도로 공급해야 함.

| 상태 | 소비 전류 |
| :--- | :--- |
| 동작 중 | 100 ~ 250 mA |
| 스톨 (끝단에서 힘을 유지) | 최대 700 mA |
| AD-USBISP의 USB 전원 권장 한계 | 100 mA |

USB 전원으로는 서보를 구동할 수 없으므로 12V 서플라이와 레귤레이터를 통해 5V를 공급함. 신호 기준을 맞추기 위해 보드와 GND를 공통으로 연결함.

### PB7 선택 근거
PB7은 OC2와 OC1C를 겸하는 핀임. Timer2는 8비트이므로 20ms 주기를 만들기 위해 큰 분주비가 필요하고, 그 결과 각도 분해능이 저하됨. 16비트인 Timer1의 C 채널로 사용함.

데이터시트에 OC1C는 ATmega103 호환 모드에서 사용할 수 없다고 명시되어 있음. 본 보드는 UART1이 정상 동작하며, UART1 역시 호환 모드에서는 존재하지 않는 기능이므로 호환 모드가 비활성 상태임이 확인됨.

## 5. 핵심 코드 및 레지스터 설정 (Key Implementation)

### Timer1 Fast PWM 설정 (hw5.c)
```c
void INIT_servo(void)
{
    DDRB |= (1 << PB7);                     // OC1C 출력

    ICR1 = 39999;                           // TOP. 40000 * 0.5us = 20ms
    TCCR1A = (1 << COM1C1) | (1 << WGM11);  // 비반전, Fast PWM 하위비트
    TCCR1B = (1 << WGM13) | (1 << WGM12) | (1 << CS11);   // 모드 14, 분주 8
}
```

| 레지스터 | 설정 | 의미 |
| :--- | :--- | :--- |
| TCCR1A, TCCR1B | WGM13:WGM10 = 1110 | Fast PWM 모드 14. TOP을 ICR1로 지정 |
| TCCR1A | COM1C1 = 1, COM1C0 = 0 | 비반전 출력. OCR1C까지 High 유지 후 Low |
| TCCR1B | CS11 = 1 | 분주비 8 |
| ICR1 | 39999 | PWM 주기 결정 |
| OCR1C | 1200 ~ 4800 | 펄스 폭 결정 |

### 주기와 분해능 계산
서보는 20ms 주기로 입력되는 펄스의 폭으로 목표 각도를 판단함.

```text
분주 8  ->  16MHz / 8 = 2MHz  ->  1틱 = 0.5us
ICR1 = 39999  ->  (39999 + 1) x 0.5us = 20.000ms  (오차 0)

펄스 0.6 ~ 2.4ms  ->  1200 ~ 4800틱  ->  3600단계
```

8비트 타이머를 사용할 경우 20ms 주기를 만들려면 분주비 1024가 필요하며, 이 경우 1틱이 64us가 되어 180도를 약 28단계로만 표현할 수 있음. 16비트 타이머는 분주비를 작게 유지할 수 있어 3600단계의 분해능을 확보함.

### 각도 변환
```c
uint16_t CONVERT_angleToUs(uint8_t angle)
{
    return (uint16_t)(PULSE_MIN_US
           + ((uint32_t)(PULSE_MAX_US - PULSE_MIN_US) * angle) / ANGLE_MAX);
}
```
`(2400 - 600) x 180 = 324000`이므로 16비트 정수 범위를 초과함. AVR의 int는 16비트이므로 `uint32_t`로 승격하지 않으면 값이 접혀 잘못된 각도가 계산됨.

SG90의 펄스 폭은 통상 1.0 ~ 2.0ms로 알려져 있으나, 실제로는 0.5 ~ 2.4ms를 인가해야 0 ~ 180도 전 범위를 사용할 수 있음. 1.0 ~ 2.0ms만 사용하면 약 90 ~ 120도 범위만 동작함. 개체차가 있으므로 끝단에서 기계적 한계에 부딪히는 소리가 발생하면 상한값을 조정해야 함.

### 입력 처리 및 예외처리
문자열로 입력된 숫자를 한 글자씩 누적하여 정수로 변환하고, 개행 문자를 만나면 검사 후 반영함.

| 입력 | 판정 | 응답 |
| :--- | :--- | :--- |
| 0 ~ 180 | 정상 | `OK: n deg (pulse nnnnus)` |
| 181 이상 | 범위 초과 | `ERROR: n is out of range (0-180)` |
| 음수 부호 포함 | 범위 미만 | `ERROR: angle < 0 (allowed 0-180)` |
| 숫자 외 문자 | 형식 오류 | `ERROR: digits only` |
| 엔터만 입력 | 무시 | 응답 없음 |

유효하지 않은 입력에서는 `WRITE_servo`를 호출하지 않으므로 모터가 움직이지 않음. 또한 누적값이 과도하게 커지는 경우를 방지하기 위해 자릿수 제한을 배치함.

### 원점 복귀
```c
WRITE_servo(HOME_ANGLE);
_delay_ms(800);
```
전원 투입 시 서보는 이전 위치에서 원점까지 한 번에 이동하며, 이 과정에서 순간 전류가 크게 흐름. 이동이 완료될 시간을 확보한 뒤 입력 수신을 시작함. 원점은 기계적 한계에 부딪힐 가능성이 낮은 중앙값 90도로 지정함.

## 6. 동작 설명 및 결과 (Results)

### 동작 시나리오
1. 전원 인가 시 Timer1 PWM을 시작하고 90도 위치로 복귀함
2. 0.8초 대기 후 UART 입력을 받기 시작함
3. 터미널에서 각도를 입력하고 엔터를 누르면 해당 위치로 이동함
4. 유효 범위를 벗어나면 경고를 출력하고 모터는 움직이지 않음

```text
SG90 servo control
HOME: 90 deg (pulse 1500us)
input 0-180 then Enter

OK: 0 deg (pulse 600us)
OK: 90 deg (pulse 1500us)
OK: 180 deg (pulse 2400us)
ERROR: 200 is out of range (0-180)
ERROR: digits only
ERROR: angle < 0 (allowed 0-180)
```

### 검증 과정에서 확인한 사항

**정수 오버플로우**
초기 구현에서 각도 계산 결과가 비정상적인 값으로 출력됨. 컴파일 시 정수 오버플로우 경고가 발생하였으며, `(2400 - 600) x 180`이 16비트 범위를 초과하는 것이 원인이었음. 계산 과정을 `uint32_t`로 승격하여 해결함.

**예외 입력 누락**
문자만 입력한 경우(`abc` 등) 아무 응답도 출력되지 않는 문제를 확인함. 숫자가 하나도 입력되지 않은 상태를 "엔터만 누른 경우"로 판정하여 조용히 넘어가는 분기에 포함되어 있었음. 잘못된 문자가 있었는지를 판정 조건에 추가하여 해결함.

**레지스터 값 확인**
각도에 대응하는 펄스 폭이 의도대로 설정되는지 OCR1C 값을 직접 확인함.

| 입력 각도 | OCR1C | 환산 펄스 폭 |
| :--- | :--- | :--- |
| 0도 | 1200 | 600 us |
| 90도 | 3000 | 1500 us |
| 180도 | 4800 | 2400 us |

ICR1은 39999로 유지되어 주기 20ms가 정확히 확보됨을 확인함.
