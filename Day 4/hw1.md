# TIMER0 / TIMER2 보고서
## 정의
TIMER0와 TIMER2는 ATmega128 내부에 있는 8비트 타이머/카운터 모듈이다. 카운터는 들어오는 클럭의 상승 엣지 개수를 세는 것이고, 타이머는 그 클럭으로 내부 클럭을 넣어서 시간을 재는 것이다. 정해진 시간마다 인터럽트를 걸어 주기 때문에 시간 지연 생성, 시계 만들기, LED 점멸, PWM을 이용한 모터 제어 등에 사용된다.

_delay_ms() 같은 함수는 CPU를 붙잡고 있어서 기다리는 동안 다른 일을 못 하지만, 타이머는 하드웨어가 알아서 세고 다 되면 인터럽트로 알려주기 때문에 그 사이에 CPU가 다른 작업을 할 수 있다는 게 가장 큰 차이다.

## 특징
- TIMER0 : 8비트(0~255) 타이머이고 분주비를 1, 8, 32, 64, 128, 256, 1024 중에서 고를 수 있다. 외부에 32.768kHz 크리스탈을 달면 비동기로 동작시켜 시계용으로 쓸 수도 있다.
- TIMER2 : 마찬가지로 8비트지만 TIMER0과 별개로 동작하기 때문에 두 개를 동시에 써서 서로 다른 주기의 작업을 병렬로 처리할 수 있다. 분주비는 1, 8, 64, 256, 1024로 TIMER0과 종류가 조금 다르다.
- 둘 다 오버플로우 인터럽트, 비교일치(CTC) 인터럽트, PWM 출력을 지원한다.
- 8비트라 최대 255까지밖에 못 세기 때문에 긴 주기를 만들려면 분주비를 크게 잡아야 한다.

## 동작 원리
타이머 클럭이 한 번 들어올 때마다 TCNT0 값이 1씩 증가한다. Normal 모드에서는 0x00부터 0xFF까지 세고 다시 0x00으로 넘어가는 순간 오버플로우 인터럽트가 발생한다. CTC 모드에서는 TCNT0이 OCR0에 적어둔 값과 같아지는 순간 0으로 초기화되면서 비교일치 인터럽트가 발생한다.

CPU 클럭을 그대로 쓰면 너무 빨라서 금방 넘쳐버리기 때문에 분주비(Prescaler)로 나눠서 느리게 만든다. 예를 들어 클럭이 16MHz이고 분주비가 256이면 16,000,000 / 256 = 62,500Hz가 되고 1카운트는 16us가 된다. 이 상태에서 255까지 세면 약 4.096ms가 된다.

주기 계산은 (분주비 / 클럭) x 카운트 수로 하면 된다. 오버플로우를 쓰면 카운트 수가 (256 - TCNT 초기값)이고, CTC를 쓰면 (OCR + 1)이다. 그래서 원하는 주기를 만들려면 분주비를 바꾸거나 TCNT 초기값(또는 OCR 값)을 바꾸면 된다.

## 사용 레지스터
- TCCR0 : 타이머 제어 레지스터. CS02~CS00으로 분주비를 고르고, WGM01/WGM00으로 동작 모드(Normal, CTC, PWM)를 정한다.
- TCNT0 : 현재 카운트 값이 들어 있는 레지스터. 직접 값을 써넣어 초기값을 바꿀 수 있다.
- OCR0 : 비교값 레지스터. CTC 모드에서는 이 값이 TOP이 된다.
- TIMSK : 인터럽트 허용 레지스터. TOIE0이 오버플로우, OCIE0이 비교일치 인터럽트 허용이다.
- TIFR : 인터럽트 발생 플래그(TOV0, OCF0). ISR로 들어가면 자동으로 지워진다.
- TIMER2는 TCCR2, TCNT2, OCR2를 같은 방식으로 사용한다.

설정 순서는 TCCR0으로 모드와 분주비를 정하고 -> OCR0(또는 TCNT0) 값을 넣고 -> TIMSK로 인터럽트를 켜고 -> sei()로 전역 인터럽트를 허용하는 식이다.

```c
TCCR0 = (1 << WGM01) | (1 << CS02) | (1 << CS01);   // CTC, 분주 256
OCR0  = 124;                                        // (124+1) x 16us = 2ms
TCNT0 = 0;
TIMSK |= (1 << OCIE0);
sei();

ISR(TIMER0_COMP_vect)
{
    tick++;      // 2ms마다 실행
}
```

## 실습에서의 적용
4일차 시계/달력 과제와 PSD 측정 과제에서 TIMER0을 CTC 모드로 두고 2ms마다 인터럽트가 걸리게 설정했다. 16MHz에 분주비 256을 쓰면 1카운트가 16us이고 OCR0을 124로 두면 (124 + 1) x 16us = 2ms가 딱 떨어진다. 이 2ms를 5번 세서 10ms(1/100초), 500번 세서 1초를 만들어 LCD에 시:분:초.밀리초를 출력했다.

처음에는 분주비를 1024로 잡았는데 이러면 10ms를 만드는 데 156.25카운트가 필요해서 소수가 생기고, 그 오차가 계속 쌓여서 시계가 조금씩 느려졌다. 그래서 나누어떨어지는 256으로 바꿨다. 분주비를 고를 때는 필요한 카운트 수가 256을 넘지 않으면서 정수로 떨어지는 값을 골라야 한다는 걸 알게 되었다.

그리고 ISR 안에서 LCD 출력까지 하면 인터럽트 처리 시간이 길어져서 주기가 밀리기 때문에, ISR에서는 카운터만 올리고 실제 출력이나 계산은 main 루프에서 처리하도록 했다.

## AI 활용
(1) 원하는 인터럽트 주기를 만들기 위해 분주비와 TCNT0(OCR0) 초기값을 계산하는 방법을 AI를 통해 참고하였다. 분주비에 따라 카운트 값이 소수가 되면 오차가 생긴다는 점을 확인하였다.

(2) 오버플로우 모드와 CTC 모드의 차이, CTC에서 OCR 값이 TOP이 되어 자동으로 TCNT가 0으로 초기화된다는 점을 AI를 통해 학습하였다.

(3) ISR과 main 함수가 같은 전역 변수를 동시에 사용할 때 값이 깨질 수 있다는 점을 AI를 통해 학습하였다. 변수를 volatile로 선언하고, 여러 바이트짜리 변수를 읽을 때는 cli()로 잠시 인터럽트를 막고 복사한 뒤 sei()로 다시 켜는 방법을 적용하였다.

(4) TCCR0, TCNT0, OCR0, TIMSK 등 타이머 관련 레지스터의 각 비트 역할과 설정 방법을 이해하기 위해 데이터시트와 함께 AI를 활용하였다.

(5) TIMER0과 TIMER2의 분주비 선택 항목이 서로 다르다는 점을 AI를 통해 확인하였다.
