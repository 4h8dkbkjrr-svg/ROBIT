# TIMER1 / TIMER3, PWM 보고서
## 정의
TIMER1과 TIMER3은 ATmega128 안에 들어 있는 16비트 타이머/카운터다. TIMER0, TIMER2가 8비트라 0~255까지밖에 못 세는 것과 달리 0x0000부터 0xFFFF까지 65535를 셀 수 있다. 그래서 분주비를 크게 잡지 않고도 긴 주기를 만들 수 있고, 같은 주파수를 만들더라도 카운트 칸이 훨씬 많아서 PWM 해상도가 높다.

PWM(Pulse Width Modulation)은 정해진 주기 안에서 High로 있는 시간의 비율(듀티비)을 바꿔서 평균 전압을 조절하는 방식이다. 모터 속도를 줄일 때 전압 자체를 3V로 낮추는 게 아니라, 5V를 빠르게 켰다 껐다 하면서 켜져 있는 비율을 60%로 만들어 평균 3V처럼 보이게 하는 것이다. 소자 입장에서는 완전히 켜지거나 꺼진 상태만 있어서 전압을 직접 떨어뜨리는 방식보다 열 손실이 적고, MCU가 디지털 출력만으로 아날로그 제어를 흉내낼 수 있다.

## 특징
- 16비트(0x0000 ~ 0xFFFF) 카운터다. 고정 TOP을 쓰는 PWM 모드에서는 해상도가 8/9/10비트로 정해져 있지만, ICR1이나 OCR1A를 TOP으로 쓰는 모드를 고르면 원하는 주기에 맞춰 최대 16비트까지 해상도를 잡을 수 있다.
- 비교 출력 채널이 A, B, C 세 개다. TIMER1은 OC1A(PB5), OC1B(PB6), OC1C(PB7)로 나오고 TIMER3은 OC3A(PE3), OC3B(PE4), OC3C(PE5)로 나온다. 세 채널은 카운터를 공유하기 때문에 주기는 같고 듀티만 각각 다르게 줄 수 있다. 모터 두 개를 같은 주파수로 따로 제어할 때 이 구조를 쓴다.
- 인터럽트가 오버플로우, 비교일치 A/B/C, 입력 캡쳐 네 종류다.
- 입력 캡쳐(Input Capture)는 ICP1 핀에 신호가 들어온 순간의 TCNT1 값을 ICR1에 자동으로 복사해 주는 기능이다. 신호가 들어온 시각을 하드웨어가 붙잡아 주기 때문에 초음파 센서 에코 펄스 폭 측정처럼 시간을 재야 하는 곳에 쓴다.
- TIMER3은 TIMER1과 구조가 완전히 같고 레지스터 이름의 1이 3으로 바뀔 뿐이다. 다만 인터럽트 허용과 플래그가 TIMSK/TIFR이 아니라 ETIMSK/ETIFR에 따로 나와 있어서 이 부분만 헷갈리기 쉽다.
- 16비트 레지스터는 8비트 버스로 두 번에 나눠 접근하기 때문에 임시(TEMP) 레지스터를 거친다. 쓸 때는 상위 바이트 먼저, 읽을 때는 하위 바이트 먼저 접근해야 값이 깨지지 않는다. avr-gcc에서 TCNT1처럼 16비트 이름으로 한 번에 쓰면 컴파일러가 순서를 알아서 맞춰준다.

## 동작 원리
타이머 클럭이 한 번 들어올 때마다 TCNT1이 1씩 증가하고, TOP까지 올라가면 모드에 따라 0으로 돌아가거나 다시 내려온다. 주기는 T = (분주비 x 카운트 수) / F_CPU 로 계산한다.

PWM에서는 TOP이 주기를 결정하고 OCR 값이 듀티를 결정한다. 카운터가 올라가다가 OCR 값을 지나는 순간 출력핀이 바뀌기 때문에, OCR을 TOP에 가깝게 둘수록 High 구간이 길어진다.

**Fast PWM** : 0에서 TOP까지 한 방향으로만 세고 TOP에 닿으면 바로 0으로 떨어진다. 톱니파 모양이다. 한 주기에 카운트를 한 번만 하므로 같은 조건에서 주파수가 높다.
- f = F_CPU / (N x (1 + TOP))

**Phase Correct PWM** : 0에서 TOP까지 올라갔다가 다시 0까지 내려온다. 삼각파 모양이다. 올라갈 때와 내려올 때 각각 비교일치가 생기므로 펄스가 중심을 기준으로 좌우 대칭이 되고, 듀티를 바꿔도 펄스의 중심 위치가 움직이지 않는다. 대신 한 주기에 두 번 세기 때문에 주파수는 절반이 된다.
- f = F_CPU / (2 x N x TOP)

비반전(non-inverting) 출력은 올라가는 도중 비교일치에서 핀을 Low로 내리고 BOTTOM에서 다시 High로 올린다. 그래서 OCR 값이 클수록 듀티가 커진다. 반전(inverting) 출력은 반대로 동작한다.

과제에서 요구한 5kHz를 16MHz 기준으로 계산하면 이렇게 된다.
- Fast PWM, 분주비 1 : 1 + TOP = 16,000,000 / (1 x 5,000) = 3200 이므로 ICR1 = 3199
- Phase Correct, 분주비 1 : TOP = 16,000,000 / (2 x 1 x 5,000) = 1600 이므로 ICR1 = 1600

분주비를 8로 두면 각각 399, 200이 되어 역시 정수로 떨어지지만 카운트 칸이 8분의 1로 줄어 듀티를 잘게 나누기 어려워진다. 5kHz는 분주비 1로도 TOP이 65535를 넘지 않으므로 분주비 1을 쓰는 편이 해상도 면에서 유리하다. 교육자료의 20kHz 예시에서 분주비 64, 256, 1024가 소수나 음수가 나와 못 쓰는 것도 같은 이유다. 분주비는 TOP이 16비트 범위 안에 들어오는 선에서 가장 작은 값을 고르면 된다.

## 사용 레지스터
### TCCR1A (제어 레지스터 A)
| 비트 | 이름 | 역할 |
|---|---|---|
| 7:6 | COM1A1, COM1A0 | 채널 A 출력 모드 (10 = 비반전, 11 = 반전) |
| 5:4 | COM1B1, COM1B0 | 채널 B 출력 모드 |
| 3:2 | COM1C1, COM1C0 | 채널 C 출력 모드 |
| 1:0 | WGM11, WGM10 | 파형 생성 모드 하위 2비트 |

COM 비트를 00으로 두면 핀이 일반 I/O로 남아서 OCR을 아무리 바꿔도 파형이 안 나온다. 그리고 이 비트를 켰더라도 DDRB로 해당 핀을 출력으로 설정하지 않으면 역시 신호가 나오지 않는다.

### TCCR1B (제어 레지스터 B)
| 비트 | 이름 | 역할 |
|---|---|---|
| 7 | ICNC1 | 입력 캡쳐 노이즈 제거. 켜면 4클럭 동안 값이 유지될 때만 인정하므로 신호가 4클럭 지연된다 |
| 6 | ICES1 | 캡쳐 엣지 선택 (1 = 상승, 0 = 하강) |
| 4:3 | WGM13, WGM12 | 파형 생성 모드 상위 2비트 |
| 2:0 | CS12, CS11, CS10 | 클럭 소스와 분주비 (1, 8, 64, 256, 1024, 외부 T1핀) |

CS 비트가 000이면 클럭이 끊겨 타이머가 정지한다. 그래서 설정을 다 끝낸 뒤 마지막에 CS를 써 넣으면 타이머가 그 시점부터 돌기 시작한다.

### 파형 생성 모드 (WGM13:10)
| WGM13:10 | 모드 | TOP |
|---|---|---|
| 0000 | Normal | 0xFFFF |
| 0100 | CTC | OCR1A |
| 1010 | Phase Correct PWM | ICR1 |
| 1110 | Fast PWM | ICR1 |

WGM 비트 4개가 TCCR1A와 TCCR1B에 2개씩 쪼개져 있어서 한쪽만 설정하고 넘어가는 실수를 하기 쉽다. Fast PWM(1110)은 WGM13, WGM12를 TCCR1B에, WGM11을 TCCR1A에 넣어야 한다.

### 나머지
- **TCCR1C** : FOC1A/B/C 비트만 있다. 비 PWM 모드에서 비교일치가 일어난 것처럼 출력을 강제로 한 번 바꿀 때 쓴다. PWM 모드에서는 쓰지 않으므로 보통 건드리지 않는다.
- **TCNT1H, TCNT1L** : 현재 카운트 값. 코드에서는 TCNT1로 한 번에 접근한다.
- **OCR1AH/AL, OCR1BH/BL, OCR1CH/CL** : 비교값 레지스터. PWM에서 듀티를 결정한다. PWM 모드에서는 이중 버퍼로 동작해서 값을 아무 때나 써도 실제 반영은 다음 주기 경계에서 일어난다. 덕분에 펄스 중간에 값이 바뀌어 이상한 파형이 나오는 일이 없다.
- **ICR1H, ICR1L** : 입력 캡쳐 값이 저장되는 레지스터. Fast PWM과 Phase Correct PWM에서는 TOP 값으로 쓴다. 단 ICR1을 TOP으로 쓰는 순간 입력 캡쳐 기능은 같이 쓸 수 없다. 캡쳐도 필요하면 OCR1A를 TOP으로 쓰는 모드를 골라야 한다.
- **TIMSK** : TIMER1 인터럽트 허용. TICIE1(캡쳐), OCIE1A, OCIE1B, TOIE1이 들어 있다.
- **ETIMSK** : 나머지 인터럽트 허용. OCIE1C와 TIMER3 관련 비트가 전부 여기 있다. 채널 C만 TIMSK가 아니라 ETIMSK에 있는 게 함정이다.
- **TIFR, ETIFR** : 인터럽트 발생 플래그(ICF1, OCF1x, TOV1). ISR로 들어가면 자동으로 지워지고, 직접 지울 때는 0이 아니라 1을 써야 지워진다.
- **SFIOR** : PSR321 비트로 TIMER1/2/3의 분주기를 한 번에 초기화한다. 여러 타이머의 시작 시점을 맞출 때 쓴다.

설정 순서는 DDR로 OC핀을 출력으로 잡고 -> TCCR1A/B로 모드와 출력 방식을 정하고 -> ICR1에 TOP을 넣고 -> OCR1x에 듀티를 넣고 -> 마지막에 CS 비트로 클럭을 넣어 타이머를 출발시키는 식이다.

```c
DDRB |= (1 << PB5) | (1 << PB6);                    // OC1A, OC1B 출력

TCCR1A = (1 << COM1A1) | (1 << COM1B1) | (1 << WGM11);   // 비반전, Fast PWM
TCCR1B = (1 << WGM13) | (1 << WGM12) | (1 << CS10);      // TOP = ICR1, 분주 1

ICR1  = 3199;        // 16MHz / (1 x 3200) = 5kHz
OCR1A = 1600;        // 듀티 50%
```

## 실습에서의 적용
5일차 과제는 L298N 모터드라이버를 TIMER1 PWM으로 제어하는 내용이다. 보드에서 ENA가 PB5(OC1A), ENB가 PB6(OC1B)에 물려 있어서 TIMER1의 A, B 채널을 그대로 쓸 수 있다. 방향은 PWM이 아니라 IN1~IN4(PB0~PB3)의 조합으로 정한다. IN1=1, IN2=0이면 정회전이고 반대로 하면 역회전, 둘 다 같은 값이면 정지다. 즉 속도는 OCR1A가, 방향은 IN 핀이 담당하고 이 둘은 서로 독립이다.

여기서 중요한 건 방향을 바꿀 때 듀티를 먼저 0으로 내리고 IN 핀을 바꾼 뒤 다시 올려야 한다는 점이다. 모터가 돌고 있는 상태에서 방향만 뒤집으면 역기전력 때문에 순간 전류가 크게 튀어서 드라이버에 무리가 간다.

5kHz를 쓰는 이유는 사람이 들을 수 있는 대역(약 20kHz 이하)에 걸치기는 하지만 저주파에서 나는 심한 소음은 피하면서, 주파수를 너무 올렸을 때 생기는 스위칭 손실도 줄일 수 있는 절충점이기 때문이다. 주파수를 너무 낮추면 모터가 덜덜 떨리고 소리가 커진다.

과제 2에서는 PF0(ADC0)에 물린 가변저항 값으로 속도와 방향을 같이 정한다. ADC가 10비트라 0~1023이 나오는데, 가운데 511 근처를 정지로 두고 위쪽이면 정회전, 아래쪽이면 역회전으로 나눈 다음 중심에서 떨어진 거리를 듀티로 환산하면 된다. 가운데에는 죽은 구간을 조금 둬야 손을 안 대도 모터가 떨리지 않는다. 환산한 OCR1 값은 LCD에 띄우고 역방향일 때는 앞에 -를 붙여서 표시한다.

Phase Correct 모드도 같은 5kHz로 맞추려면 ICR1이 3199가 아니라 1600이 된다. 공식이 다른데 TOP 값을 그대로 두면 주파수가 절반으로 떨어지므로 모드를 바꿀 때 TOP도 같이 계산해야 한다. 모터 제어에서는 둘 다 무난하지만, 듀티를 자주 바꾸는 상황에서 펄스 중심이 흔들리지 않는 Phase Correct 쪽이 진동이 덜한 편이다.

## AI 활용
(1) Fast PWM과 Phase Correct PWM의 주파수 공식이 왜 다른지(한쪽은 1 + TOP, 다른 쪽은 2 x TOP) 이해하기 위해 AI를 활용하였다. 카운트 방향이 단방향인지 왕복인지의 차이에서 나온다는 점을 확인하였다.

(2) 원하는 PWM 주파수에 맞춰 분주비와 ICR1 값을 계산하는 방법을 AI를 통해 참고하였다. TOP이 16비트 범위를 넘지 않는 선에서 분주비를 작게 잡아야 해상도가 높아진다는 점을 확인하였다.

(3) WGM 비트 4개가 TCCR1A와 TCCR1B에 나뉘어 있는 구조와, 각 모드 조합에서 TOP이 무엇이 되는지를 데이터시트와 함께 AI를 활용해 정리하였다.

(4) 16비트 레지스터에 접근할 때 임시 레지스터를 거치기 때문에 상위 바이트부터 써야 한다는 점, 그리고 avr-gcc가 16비트 이름으로 접근하면 순서를 자동으로 맞춰준다는 점을 AI를 통해 학습하였다.

(5) OCR 레지스터가 PWM 모드에서 이중 버퍼로 동작해 값이 주기 경계에서 반영된다는 점을 AI를 통해 확인하였다.

(6) OCIE1C와 TIMER3 관련 인터럽트 허용 비트가 TIMSK가 아니라 ETIMSK에 있다는 점을 AI를 통해 확인하였다.

(7) 모터 방향을 바꿀 때 역기전력 때문에 듀티를 0으로 내렸다가 바꿔야 한다는 점, 그리고 PWM 주파수를 5kHz 정도로 잡는 이유를 AI를 통해 참고하였다.
